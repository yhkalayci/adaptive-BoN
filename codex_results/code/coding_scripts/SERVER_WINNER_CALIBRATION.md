# Server handoff: winner-calibrated top-three coding

Branch: `dmrl-alignment-server-20260923`.

This experiment fits one fixed isotonic score-to-utility map using exact
best-of-N winner weights for N = 10, 16, 32, 64, 128, 256, 512. Four-fold
problem-grouped cross-validation within each outer calibration split selects
the mixture of ordinary-response and winner weights. Test correctness does
not choose the map or policy settings. Ten original splits and 37 prices
($1–$10 per million output tokens) are evaluated.

## Run from the repository root

Use Python 3.11 or newer with NumPy and SciPy (`scipy.optimize.isotonic_regression`
is required). Scikit-learn is not required for this experiment; original
calibration profiles are included.

```sh
python -m venv .venv
.venv/bin/python -m pip install numpy 'scipy>=1.12'
.venv/bin/python codex_results/code/coding_scripts/coding_winner_map_scan.py \
  --source codex_results/code/coding_prices1_2_step025_20260923 \
  --reference codex_results/code/coding_top3_mean_median_prices1_10_20260924 \
  --data /YOUR/SERVER/PATH/coding_correctness_rewards.jsonl \
  --output codex_results/code/winner_calibration_server_run
```

The output directory must not already exist. `--splits 1` performs a shorter
smoke run. The data file must match SHA-256
`5d4756a4e19ee3c4bf006a4bf9d7c02b7d472376bf8c8ac7c8f1a1b9dae8ae79`.
It contains 137 filtered problems, each with 512 candidates and recorded
`output_tokens`. Raw response data and archives are not included in this push.
This is a CPU cached-data replay; no new LLM generation is performed.

Three arms are reported separately: changing only the map with old settings
frozen, retuning settings using predicted profit, and retuning with actual
calibration correctness profit. All use top-three/full-history statistics,
plain mean cost, a minimum selected from 10–512, and a cap of 512. The latter
two arms retain the known risk of tuning on only 24 calibration orderings.
Calibration improvement does not itself guarantee profit improvement or DMRL.

The standalone online policy is `AdaptiveCoding.from_paper_settings`; its
explicit parameters and a fitted `CodingProfile` reproduce the experiment's
top-three/full-history rule. Legacy constructor defaults remain unchanged.

Completed local results, once pushed, are under
`codex_results/code/coding_winner_map_prices1_10_20260924/`. Result profiles,
selected settings, aggregate tables, and manifests are retained. Larger
per-problem replay tables may remain local and can be regenerated by the command
above. These experiments are exploratory on a reused cohort; the paper has not
been changed.
